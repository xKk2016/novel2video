| 你发现的问题 | 真正的根因 | 证据 |
| --- | --- | --- |
| ①分镜长度都一样、封顶 5 秒，台词动作做不完 | **时长被写死在代码里，不是模型限制。** `templates/h3_*.json` 里 `length: 124` 固定不变，`comfyui_client.py` 提交时从不改写它；分镜里的 `duration` 字段只在拼接时用过、从未传到生成端。而 H3 节点自身写着训练范围 **124~362 帧（5.17~15.08 秒）**——能力一直够，是我们自己锁死。 | 48 个片段实测全部 `00:00:05.17`；40 条台词里 **32 条装不下**，镜33 需 47.5s 只给 5.17s |

| ③方源背影不像本人 | **背面参考图从未被使用。** `refs/fangyuan_*_back.png` 一直躺在硬盘上，但 `config.json` 只挂了 front/side/face 三张；同时 prompt 里**没有 `<Picture N>` 引用标记**，参考图"挂上了却没被点名"；外貌串也只描述正脸（眼型/神情），没有任何背面特征。 | R2V 参考图清单 = 3 张，其中 0 张背面 |

## 二、本次修复

### 1. 代码：让时长真正生效

- `comfyui_client.py` 新增 `snap_length()` / `apply_length()`：提交前把该镜帧数写进 `MiniMaxH3ImageToVideo` / `MiniMaxH3ReferenceToVideo` 的 `length`，并吸附到模型要求的 17k+5 网格。
- `generate(...)` 新增 `length` 参数；`novel_to_video.py` 每镜自动带入 `s['length']`，日志同时打印 `时长/帧数` 便于核对。
- 旧行为：模板 124 帧 → 每镜 5.17s。新行为：**每镜按自己的时长生成**。

### 2. 配置：补上背面参考图

- `config.json` 的 `ref_images` / `ref_images_by_scene`（场1 成年版、场2/场4 少年版）全部由 3 张扩到 **4 张，加入 `*_back.png`**；顺序固定为 1=正面全身、2=侧面全身、3=面部特写、4=背面全身，与 prompt 里的 `<Picture N>` 一一对应。
- 主角镜 prompt 一律显式写 `<Subject 1>` + `<Picture 1~4>` 引用；背影镜改为优先引用 `<Picture 4>`。
- 背影镜注入**背面口径**外貌串（`FY_BACK_APPEARANCE`）：只描述后脑、垂在黑袍背面的长发、背后的腰带结，并显式写 `no face visible, no eyes visible` —— 原来的外貌串含"眼型/神情"，会把模型诱导成转身露脸。

### 3. 分镜：按台词与镜头内容重新分配时长

- 分配规则：对白镜 = 台词字数 ÷ 4.2 字/秒 + 1.0 秒呼吸缓冲，向上取到 H3 帧档（5.17/5.88/6.58/7.29/8.00/8.71/9.42/10.12/10.83 秒）；无台词的环境/动作镜 5.17~6.58 秒。
- 装不下的长台词一律**拆成多个连续镜**（同说话人、同空间、切机位），不再一字不改地硬塞。
- 旁白大幅精简（旁白是超载重灾区），人物对白保持原有语气与信息。
- 附带修复：无主角的**人物镜**改走"文字锚"而非"空景锚图当首帧"（原逻辑会要求模型在一张空山巅/空走廊上加出一张人脸，神态必崩）。
